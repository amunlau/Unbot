# 在原文上标注可复核的问题

作者请你检查 AI 味、突兀表达、逻辑或整体行文时，交付带定位的审阅结果。编辑结合全文决定哪些地方影响理解，再将意见放入审阅副本。用户只需提供稿件。

## 如何决定是否标

先读标题、摘要、章节和结论，识别论文、报告或工程规范的体裁。长文按章节顺序覆盖，留意跨段复述、比较对象更换，以及图表与正文之间的限定是否一致。再回到候选原句，与前后段、相关表注和术语定义对照。判定“全文缺少某项”须核对完整的相关材料。只审摘录、缺附件或有未读区域时，在覆盖说明中写明尚待核对的图号、引文或定义；摘录内能独立确认的问题仍可标注。没有问题的段落允许零批注。

## 批注分类

每条新意见以 **【大类｜具体问题】** 开头。用原句选区、逐字引文或图表区域定位问题，再用一两句话说明判断依据、对理解或执行的影响，以及最小修改或核实办法。具体问题写“图例遮挡纵轴单位”“比较对象未交代”等读者可以核查的现象。文件内批注、独立意见单和聊天审阅均采用这一写法。

大类说明问题成因，不代表每条意见都是已证实的错误。依据[三种处理程度](coherence-review.md#判断程度与处理)，在批注正文中说明是确认的冲突、需核实的含义，还是具体的可读性建议；不另加类别或数据字段。原关系可以成立，但对象或范围切换造成回找时，可写“可读性建议：……”，说明障碍及最小改法，不称原句逻辑不成立。仅仅存在更显式、更紧凑或段数更少的写法而没有具体障碍时，不立项。结构建议说明取消边界解决了哪项重复、回找或被拆断的支撑关系；主题相近和篇幅较短本身不足以支持合段。冗余的删减建议须辨明其是否还承担强调、警示或导航作用，纯粹的措辞取舍不写成必改缺陷。同一范围问题尽量合并定位，也不因意见降为建议就遗漏确实影响理解的转向。

**章节入口单独验收。** 按[入口规则](coherence-review.md#章节入口的重要规则)检查标题与首段是否就近提供对象、当前问题和必要联系。入口主要依赖模糊回指、须回到前节才能建立话题时，即使含义最终可恢复，也应标“【篇章与逻辑｜章节入口缺少对象定位】”；已点名但从方案转执行等关系未交代时，可标“【篇章与逻辑｜章节入口未交代说明任务的转换】”。说明具体障碍，并给有依据的承接、直接点名或节号加名称方案。可明确这是应改善的表达问题，不据此断言技术结论错误；标题和正文已自然完成定位与承接的，仍不立项。不增设第七类或数据字段。

**段落边界双向检查。** 按[完整论证判据](coherence-review.md#完整论证优先)同时查该分未分和不必要的分段。后段直接解释、例证或限定前段且合并仍便于阅读时，可标“【篇章与逻辑｜同一论证被不必要地拆分】”，指出两段共同回答的问题、应取消的边界及合并理由；选取能定位的一处原句，另一段位置写入说明，不伪造跨段选区。不能仅因段落短就立项，也不能只用“两个功能不同”否定合并。保留原文的审阅任务给具体方案；不得把段落组织建议称为已证实的技术错误。

| 大类（工具代码） | 英文标签 | 判据与具体问题示例 |
| --- | --- | --- |
| AI味与文风（`style`） | Formulaic wording and style | 已有信息明确，但句子重复作空泛评价，或套用与内容无关的铺垫、强调和排比。也包括“同层限定叠加”“重复免责”“标题与首句复述”“虚假范围”等具体表现。指出它重复了哪句话，或删除后哪些事实、限定仍完整；独立限制和真实审稿回应保留。不要据此推断作者身份。正反例见[去 AI 味与文风](style-review.md)。 |
| 篇章与逻辑（`logic`） | Logic and coherence | 句段或页面之间的关系不成立、必要前提缺失，或话题与指代切换造成可具体说明的回找和重读。例如“概念先用后释”“主题跳跃且由部件计时外推系统指标”“把时间先后写成因果”“结论改换了所回答的问题”“后文丢掉了仍然有效的限定”“方法段混入无功能的包装说明”。指出前提所在处、缺失的推理步骤、后文越界的限定原句，或本应承接的对象与实际转向。 |
| 格式与排版（`format`） | Formatting and layout | 版面影响阅读，或可指出违反了哪条适用的模板要求。例如“图例遮挡纵轴单位”“同级标题编号不连续”“正文引用了不存在的图号”“表题放在表下”“交叉引用显示“错误！未定义书签””“目次或页眉与正文标题不一致”“页底裁切了验收限值和结论”“可见页残留模板占位符”“对象被移出画面”“采用 SI 时量值与单位之间缺少空格”“正文引用了文献表没有的序号”。未指定模板时，保留清楚、一致的合理版式。条目与正反例见[格式与版式审阅](format-review.md)。 |
| 文字与语法（`language`） | Language and grammar | 可以按原意修正的文字错误，例如“‘采样率’误作‘采洋率’”“英文主谓不一致”；也包括可具体说明的多层修饰或动宾关系不清。给出原意可确定的最小改法，不把单纯句长或措辞偏好标为语法错误。 |
| 事实与技术（`technical`） | Factual and technical accuracy | 已有原始记录、定义或图表能证实矛盾，或歧义会改变执行要求。例如“A、B 组的数值对调”“中英文摘要的组别数值对调”“摘要与正文的区间符号相反”“正文与图中的相关系数值不一致”“停机责任主体有两种读法”。引出可核对的记录或具体后果，并列冲突位置，不得擅自改数。 |
| 依据待核（`evidence`） | Evidence to verify | 关键结论所需的记录、引文或工况数据在已审范围内缺失。例如“现场复验记录缺失”“拓扑成熟度缺少对应引文”。指出应补查的具体材料。缺少记录的情况不足以判定某次活动没有发生。 |

判断要看这句话增加了什么。“具有重要的工程应用价值”只是对上句测量结果泛作评价时，标【AI味与文风｜空泛评价】。若另称“已在三个现场通过验收”，就新增了可查的活动和结果。提供的材料无法支持这一主张时，标【依据待核｜现场验收记录待核】，说明需要的记录及适用范围。若同一批次的签署记录明确记载一处未通过，则标【事实与技术｜验收结果与记录不符】。若作者直接从台架测量推出所有现场均能达标，则标【篇章与逻辑】，指出缺少哪一步论证。

数值冲突须比较同一指标、工况、单位和展示精度。例如同一相关系数在图和正文分别写作 0.72、0.73，且都保留两位小数，应标【事实与技术】并请作者核对原始计算。图中 0.726 在正文按约定写成 0.73 可以保留。若数值一致，但把次指标写成预先声明的主终点，或从部件计时外推整机达标，则在越过证据的句子标【篇章与逻辑】。[篇章衔接实例](coherence-review.md)

已能确认同口径矛盾时，即使尚不知哪个值正确，仍标“事实与技术”并列出冲突；需要作者裁定不等于只能标“依据待核”。后者用于关键记录或定义不足，尚不能确认主张或关系的情况。

一个根因在首次影响理解的位置加注，关联段或页写入说明。同一句的错字和数值错误可以分别定位时，建立两条独立意见。若必须共用一个选区且工具不支持重叠批注，优先在原处标出影响结论或操作的问题，其他独立问题在定位清单中各列一条，注明同一原句。

多条建议落在相邻句段时，按建议合并应用后的读序复读：一条删去定义、另一条却仍引用该定义，或多条都补相同条件时，应先消除建议间的冲突与重复。检查共同改动会不会改变引文支持范围或丢掉限定。只审阅也要确认建议可共同执行，但不实际替换原文。

段落问题仍使用上述六类。可写“【篇章与逻辑｜段首指代对象不清】”“【篇章与逻辑｜段内话题无交代地转换】”“【篇章与逻辑｜段落边界拆断限定关系】”或“【篇章与逻辑｜段落内容偏离小节任务】”。不能只写“衔接生硬”；应引出候选对象、实际转向和最小修法，拆段建议指明从哪句起，移位建议说明目标段或小节的作用。对象已明确但搭配不当时用“文字与语法”；真实段落标记或显示错误才用“格式与排版”。未确认的关键事实归属按需标“依据待核”，已证实的技术归属错误或会改变操作要求的歧义按“事实与技术”处理，不把同一根因重复计数。

例如，“【篇章与逻辑｜段首指代对象不清】上段依次介绍硬件、软件和云服务，末句讨论开发者。本段‘其适用需求’未说明转而讨论哪一层产品，需回找对象。建议依据材料点明对象，再写其面向的任务或应用场景；对象尚未确定时请作者核实。”仅审阅保持原文，结构调整按[编辑范围](editing-modes.md)执行。

枚举、选型与跨节问题也沿用这套分类，可写“【篇章与逻辑｜枚举范围与实际比较不一致】”“【篇章与逻辑｜判据适用对象未交代】”“【篇章与逻辑｜概述与具体示例的范围交代不足】”。说明具体覆盖项、判据或候选对象；不要求每篇稿件报齐这些现象。综合概览、清楚的局部聚焦和正常跨节回指应保留，实例与边界见[范围与承接检查](coherence-review.md#枚举比较与展开范围)。同一断点造成多个表面症状时合并意见，不因命中多个名称重复计数。

**填写意见清单。** 新建的定位数据在顶层写 `"finding_schema": 2`。每条意见的 `category` 使用表中的代码，`issue` 写具体问题，`comment` 写依据和建议。工具将三者组合成批注。默认使用中文。如要求用英文批注，在顶层写 `"review_language": "en"`（中文为 `"zh"`），并用英文填写 `issue` 和 `comment`，例如 `[Logic and coherence | Index used before its definition]`。工具生成的大类标签、行列或幻灯片定位、零项提示、HTML 标题及导航等随审阅语言切换。引文和原稿中的对象名称（如幻灯片形状名）保持原样。

**误报对照**

连续重复、条件清单、全文综合缺口及制作说明按现有六类处理，不增加“拟人度”分类。重复问题并列前后位置，说明真正新增的信息；综合缺口同时指出任务承诺与可用材料位置；动作压缩指出具体修饰关系，涉及未确定的技术主体时不凭改句补足。意见自身也须保真、清楚，不能用更强的结论或新事实示范“更有力”的表达。

复核意见时同时撤除没有具体理解障碍或证据缺口的核查要求。未判为错误但反复要求作者确认公知表达、已说明的条件或无关指标，同样会增加审阅负担；有实际影响的待核事项仍须保留。正常段落和零项结果不需要为了显示检查深度而附一串泛化建议。

- “显著提升了系统的综合效能”只有形容词，且前后未说明指标时，可询问测量对象与比较基准。若原句为“两组差异有统计学意义（p = 0.013）”，则阅读检验对象和表格；不因“显著”一词标注。
- “实现闭环赋能”且上下文未说明反馈过程，可要求写明实际动作。“闭环控制器根据压力反馈调节阀位”已给出机制，保留术语。
- 摘要与正文都报告主要结果符合文体需要。若讨论段连续两段都以“充分体现应用价值”结束且没有新增依据，可只标后一次。
- 原始报错、受访者引语、命令、公式、参考文献题名和模板规定的条文是被引用或受保护的内容。若确需提醒，选中作者围绕它所作的解释，写清区别。单个破折号、被动句、整齐列表、英语非母语表达以及作者常用语都不足以单独立项。
- 遇到中文省略主语、英文方法段使用被动或双语摘要句序不同，先按[中英文科技表达](chinese-english-style.md)判断意义。若有两个可能的施事、两组值次序颠倒或一侧把推测写成事实，批注指出相关的两处及其后果。有据可查的惯用写法保留。

## 各格式的交付

**PowerPoint。** 按[演示文稿批注与定位](pptx-review.md)选择当前文件可用的方式。文字问题给出实际页码、对象和逐字引文。图证问题若没有可引的原句，用图例、坐标轴或明确的区域定位。跨页时再给关联页，区分页面可见文字与演讲者备注。若仅能交付独立定位清单，在交付说明中标明。

**Word**。按[原生批注说明](word-review.md)定位正文或表格里的段落，生成新的 `.docx` 审阅副本。在 Word 的“审阅”面板中应能读到意见、选中对应原句。保留正文。脚本列出的未处理区域应在交付时说明；若还有待提示的问题，可用独立的“位置＋逐字引文＋意见”补充，不要把批注挂到邻近但无关的句子。对已有修订、受保护文档或旧版 `.doc`，优先通过文档编辑器处理副本；确需转换时保存为新文件，核对变换后的正文与修订状态再定位。

**TXT / Markdown。** 使用[文本批注工具](../scripts/review_text.py)。默认交付“文件名-审阅.html”。高亮标出引文，点击编号可在原句与意见间往返。Markdown 按源码显示，链接、HTML 和代码示例均作为原文保留。若用户需要原格式，交付同后缀副本，在正文后附意见。副本使用 UTF-8 编码，换行统一为 LF，行列号按原稿计算。若原稿末尾有未闭合的顶层代码围栏、HTML 注释或原样块，工具会将完整原稿放入标为“源码”的区块，再单独显示意见。应在实际阅读器中确认两部分均可见。审阅时区分作者行文与 YAML、代码、链接地址、直接引语等原样材料。

如果 Markdown 原稿含 HTML 折叠区或隐藏容器，先确认附录中的意见在目标阅读器里是否可见。遇到意见被折叠或隐藏时，在 `annotate` 命令中增加 `--source-view`，用新文件名生成同后缀副本；重开后，原稿按源码显示，意见位于独立区块。

以下命令由编辑在文稿工作目录运行，将“技能目录”替换为技能安装目录的绝对路径。中间文件保存在该工作目录或其任务子目录，只交付最终副本及必要的覆盖说明。

```text
python "技能目录/scripts/review_text.py" inspect 原稿.md --output lines.json
python "技能目录/scripts/review_text.py" annotate 原稿.md findings.json 原稿-审阅.html
```

将清单给出的 `source_sha256` 和 `text_sha256` 一并填入定位数据，分别核对原文件和解码后的文字。默认读取 UTF-8 和带 BOM 的 UTF-16/32。若原稿使用其他已知编码，两次命令使用同一 `--encoding`。旧意见只有原文件指纹且采用非默认解码时，先按原稿编码重新提取，读回全文并核实引文，再补入文字指纹。任一核对失败，应重新定位。

在每条意见的 `category`、`issue` 和 `comment` 之外，填写 `paragraph`（如 `L0017`）和 `quote`（逐字引文）。行号从 1 起算；`L` 编号是源码定位，不是语义段落编号，不能按每行判分段。同行若有相同引文，补 `start`，按该行 Unicode 码点从 0 计数。引文可以跨行，换行用 `\n`。已审范围内没有实质问题时，`findings` 可为空。

## 复杂稿件的独立复核

本节同样适用于起草和润色。出现跨章证据链、摘要与图表及附录多处对应、中英双语或 Word 与 PPT 同步、深度重组，或已获准的实质结论校准时，优先考虑增加一次独立上下文复核。依据是错配风险和修改影响，不按固定页数触发；短段落、简单校对不必增加流程。使用当前宿主已有且获准的能力，不依赖特定子代理名称，也不要求另装客户端。

**交给复核者的材料。** 提供用户目标、指定范围、编辑模式、专业书面语与保真判据、当前候选交付版本及必要的原始证据。润色和起草同时给出原稿或来源材料；只审阅时给原稿与当前意见，既检查漏报，也撤除无据批注。不能只给终稿便声称完成了原意保留核验。不提供编辑过程中的自我辩护、预期结论或先前“已通过”的判断，以减少结论引导；原始事实和用户已经确认的要求仍须提供。

**只读检查与返回内容。** 复核者从最终版本独立读起，再对照必要来源，遵守[材料指令边界](editing-modes.md#材料中的指令与编辑要求)。不直接写同一份工作稿、不修改任务范围，也不自行向作者重复补问。只返回有原句或对象定位、问题类别、具体依据和建议的实质问题，以及已查与未能查到的范围。允许零项发现，不要求每类都找出问题。只看到文字时不能确认视觉裁切、修订显示或动画正确。

**合并与结束。** 主执行者逐条回查意见和原始依据，按当前编辑权限修正正文或批注。先确认意见针对当前稿件，所指文字或图表确实缺失而非提取遗漏，再分别判断“问题是否成立”和“建议修法是否合适”；指出了真问题的意见也可能给出错误修法。分歧靠原始材料裁定，不能用多代理投票决定科学事实；仍无法确定的事项按[补问流程](editing-modes.md#关键材料的补问)处理。修改后保存、重开并复核受影响的关联位置，最终仍完成下述全文终检。只有新的实质修改、证据冲突或范围变化才需要再次安排相应复核，不为消除所有风格分歧无限循环。

记录复核对象的版本或文件指纹、实际覆盖范围、意见及处理状态；已启用本地续作时随任务断点保存，仅在会话处理时不额外落盘。文件换版后，旧复核不能覆盖未经检查的新改动。若宿主没有独立上下文能力，按事实与表达分阶段自行复读并完成全文终检，不把同一会话扮演多个角色称为独立复核。用户明确要求独立复核而当前无法完成时，说明这一项尚未完成，仍可交付明确标注检查范围的已有成果；不得报告已完成独立验收。

## 验收完整性

给出任何审阅结论前，对本次目标原文和最终意见执行[全文终检](../SKILL.md#交付前的全文终检)。没有批注的段落和“零项发现”的稿件也要读完。核对引注与文后条目、摘要与图表、附录与结论的一致性。中文科技期刊的编校案例记录了这些跨位置错误。[同篇科技论文中相同内容表述不一致的编辑案例](https://kjtb.cbpt.cnki.net/portal/journal/portal/client/paper/3cf8e9fe3398453accbe991b5f4646fb)

1. 在最终交付件中逐条回读标签、原句和邻近上下文。核对大类是否符合实际成因、具体问题是否能从引文及所指位置复核、建议是否解决该问题。留意同文重复、同句不同对象，以及上一段已提供的证据。
2. 核对实际落下的意见数与已确认条目数。不随机设定批注密度；如果只审指定范围，或图像、公式、嵌入对象中的文字未能读取，简述覆盖范围。出现定位失败时，修正选区后重新生成，禁止静默漏项。
3. 确认原稿保留、审阅副本能打开、正文和批注彼此区分，按需要抽查表格、原有批注及重复制句。仅对实际审阅范围表述“发现了哪些问题”。核查方法的依据见[研究与适用边界](detection-evidence.md)。

## 文件处理与编辑判断的复测

关于会话中断，[断点测试](../tests/test_checkpoint.py)覆盖保存进程异常退出、原稿换版、并发更新和成品找回。恢复后仍须在最终交付物上按前述步骤核对引文、覆盖范围与批注数量。

在技能目录运行 `python -B -X utf8 -m unittest discover -s tests -v`。完整用例需要 `python-docx`、`python-pptx` 和 `lxml`。[基础用例](../tests/test_review_workflows.py)覆盖重复引文、原稿变动与表格选区。[Word 边界用例](../tests/test_word_edge_cases.py)核对保护设置、合并续格与校对语言。[文本与量值用例](../tests/test_text_edge_cases.py)核对编码、Markdown 审阅附录与数字记号。[PPT 用例](../tests/test_pptx_review.py)核对放映顺序、隐藏页、对象、表格、备注及批注位置。[篇章](../tests/test_coherence_fixtures.py)、[格式](../tests/test_format_fixtures.py)和[文风](../tests/test_style_fixtures.py)的样稿测试核对材料、分类标签和文件构造。判断实际裁切要查看渲染，判断审阅质量要另用未参与编写规则的样稿，检查漏报及误报。

复测全文终检时，可用三类短稿。第一份保留两版摘要中的所有数值，仅调换一版的组别，并在附录限定工况，核对是否同时发现数值归属错误和越过附录边界的结论。第二份使用中英对应的工程许可条款，其中英文有合理的被动句，检查是否能保留原文并给出零项意见。第三份让正文与摘要的计数冲突，且唯一原始图表未提供，检查是否同时指出两处位置、统计时段及证据缺口，避免替作者选定数值。

验证材料取舍时，用同一材料池分别给出选型、操作或项目进展等不同读者任务，在执行前为各任务标明必需、合理可选与可省的信息，并混入少量真实但无关的细节。核对选择是否随任务变化、关键事实和限制是否仍完整，而非只统计字数或开头长度。用途取舍限于起草或已授权的内容整理，不把测试中的省略要求带入保留独立信息的普通润色。这是技能开发的专项验证，不增加每次写作的交付流程。

[篇章样稿](../tests/fixtures/coherence/)同时覆盖摘要与表格可相互印证、组别或符号确有冲突、以及结论丢失已测工况等情况。[格式样稿](../tests/fixtures/format/)覆盖交叉引用、参考文献序号、单位空格，以及可见页和隐藏附录中的定义。复测幻灯片时要对照真实输出，区分“越过框底但文字完整”和“读者看不到关键字”。Word 样稿分别记录了打开副本时的显示与刷新相关域后的结果。交叉引用报错的具体文字可能随环境变化；手册中逐字引用的错误提示要按上下文保留。先按[实际阅读与讲解路径](format-review.md#7-ppt-把必要定义只放在隐藏附录)核对定义是否在使用前可得。确认存在缺口后，若定义仅在讲者备注中，批注写明“仅在备注中给出定义”；若位于隐藏页，则注明具体页码。不能仅因存放位置判错。[文风样稿](../tests/fixtures/style/)要求保留真实列举、可核实的第一人称和得体的英文被动句，并在现场复验依据缺失时要求补查记录。篇章和文风目录各有一份另写的复测记录，可用于编辑演练。
