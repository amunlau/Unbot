# 多节技术报告的结构与文风审校

逐句读来通顺的报告，合起来仍可能像重复填写的表单。审读整章或多对象报告时，先并读目录、相邻小节和各章总结，再回到原段核实。起草时可用同一方法检查大纲和初稿。只处理一个短段时，读够能辨明语义的上下文即可。

沿用[原有编辑权限](editing-modes.md)。仅审阅时给出原文位置、阅读困难和可行改法。标准润色可删并重复且没有独立信息的句子或整段。需要合并两个论证段、改标题或调整表列时，已获相应授权的直接改，其余列出具体建议。起草时依据任务和材料组织各节。规范条款须保留义务强度，部署手册须保留必要操作，产品发布说明中版本清单本就是读者的查找对象。

遇到同类问题而材料或权限不同时，按[各类修法的适用情形](repair-options.md)选择处理方式。指南保留能解决不同阅读困难的做法，单篇稿件只执行与实际问题相符的选项。

## 比较目录和段落承担的问题

起草时先想清楚读者读完每节应能回答的问题，并找到支撑答案的材料。审阅现稿则反过来，从各节能给出的答案检查提纲。整章或多章审读时逐项检查以下六处，只在找到具体阅读困难时提出意见。

| 篇章问题 | 怎样从原稿核实 | 起草或获准改结构时怎样处理 |
| --- | --- | --- |
| 段长和句数趋同 | 连读相邻段，看同一机制是否每写几步就被小结截断，单一结果之后是否补了泛评。 | 把触发、动作和直接结果讲到读者能跟上，再决定在哪里分段。一个数字连同工况已回答问题时，可以独立成段。各自完整的等长步骤可以保留。 |
| 小节详略失衡 | 对照核心机制、支撑机制和背景业务，指出读者复述核心过程时缺的那一步，再看背景有无挤占篇幅的重复事件。 | 核心节依材料补算例、图中细节或失效条件，支撑节写明读懂主线所需的环节。背景可压缩，需查日期和状态的事项可作年表。末段只有复述时可直接删，有独立结论时保留。 |
| 同级标题同构 | 把标题与本节实际解释的对象对照。换到另一节仍合适的标题，究竟是固定栏目，还是遮住了机制差异？ | 简介可直接用对象名，机制节可用具体动作或命题。只谈信用流控可题为“逐跳信用流控”，还详细讨论其他网络时应扩大题意。两种模式确实逐项比较时，保留并列标题。 |
| 章节和总结互为镜像 | 并读各章目录与总结的首末句，将判断分别指回本章正文，看同一总结框架是否迫使某章补写没有证据的趋势或代价。 | 保留任务规定的比较维度，其余小节按对象安排数量、顺序和详略。总结从本章已有依据的结果或取舍写起。引用测量值时交代工况，解释原因时核对正文是否给出了依据。 |
| 通用工程原理跨章重复 | 选两处相似段落，暂时遮住对象名，找出两处各自新增的事实。若两处都有测量值，核对配置、单位或负载有何不同。 | 让证据最充分的一节承担原理解释，其余节转入本对象的具体机制、代价或验收条件。材料支持定量说明时给数值与条件。独立阅读的章节就地保留所需定义和前提。 |
| 孤段与一段多题并存 | 看单句段能否独立回答一个问题，还是必须连同上下文才知道它在限定什么。对长段标出读者的问题在哪一句改变，例如从“采集哪些事件”转到“怎样解释测量值”。 | 将依附于计划的状态贴回具体计划，独立的负结果可留作短段。多题段从话题转换的第一句拆开，核对各自的证据、引文和所指。拆开的段落说完即可结束。 |

长短由内容决定。字数、句数、同一标题构式或词频可提示从哪里读起。引用参照稿或报告统计时，说明所比较的正文范围与计数单位（如段落或小节）。个案中的篇幅、分布和比例只用来说明该稿。作者或稿约有明确字数要求时，在相应限额内安排详略。只含一个章节的任务，检查其中实际可比较的范围。

**小节入口。** 连读前一节的最后一个事实与本节首句。上一节给出接收端缓冲区容量，下一节解释流控时，可从发送端怎样知道还有多少可用空间谈起，再据材料说明具体动作。也可从本节适用的条件直接起笔。标题或首句已经交代关系时，直接往下写。独立的背景或新对象可从其独有事实起笔。

**材料薄弱的章节。** 先找出可核的规格、观察或机制图。只有一项规格，只要它回答读者关心的问题，也值得清楚地列出。专利申请的示意图可用来说明申请中描述的步骤，归属与适用范围随图保留。相邻两节若只能共同回答一个问题，可以合写。缺少关键信息时，只说明它影响哪项判断。材料没有报告结果时，不能据此写成试验尚未进行或已失败。计划状态已交代、读者也无须据此比较实测收益时，可以就此收笔。固定栏目仍按任务保留，正文可以很短。

稿件较长时，可用只读的[篇章取样工具](../scripts/prose_profile.py)辅助定位。在终端运行 `python "<技能目录>/scripts/prose_profile.py" "<稿件.docx>"`，也支持 Markdown。输出 JSON 的 `sections` 按识别到的标题层级列出直属正文段的位置、开头和近似末句。Word 的 `B` 编号是主文档块序号，Markdown 的 `L` 编号是源码行号。可先看相邻等长段的样例，再看各小节最后一段和同级标题。Word 首个可识别标题之前若有目录，目录之前的无标题文字可能随前置材料一并略过。最后一个可识别目录项之后、首个标题之前的无标题引言可取样。复杂修订的最终显示、表内文字、扫描页及复杂排版均须对照原稿。词组命中不代表句子多余，读者也可能在完全没有这些词的位置反复读到同一结论。

比较小节详略时，`sections[].direct_chars` 只计该标题直接统领的正文，`subtree_chars` 连同下级小节一起计数。两者均略过表内文字和题注。核对图表时，`figure_table_mentions.items` 按可见的中文“图／表＋阿拉伯编号”列出题注候选、正文提及及首提相对题注的位置。返回 `no_body_mention` 时，回原稿核实范围合引、省略编号的列举、英文或附录编号，以及读者是否已从邻文获得指向。Word 域显示的编号还要核对实际目标。[图表引用的双向检查](format-review.md#1-图表公式编号与正文指向)

## 并读段末和小节末

把相邻数段的末句连起来读，再看同章几个小节如何结束。遇到反复出现的“应当”“取决于”“不能据此”，指出它限定哪项主张、省略时读者可能怎样误读，以及紧邻文字是否已说清。直接回答本节问题的验证状态可以放在首句。核对材料中写的是“尚未完成验证”还是“已测且未通过”，保留两种状态的区别。

| 末句实际提供的信息 | 编辑决定 |
| --- | --- |
| 版本支持状态、负结果、测试工况、证据身份，或规定读者必须做什么 | 保留并贴近相应对象。例如部署说明明确“该版本的分离模式尚未完成内部验证，建议采用聚合模式”，两个事实均须可见。 |
| 换成另一个产品仍适用的选型提醒 | 技术调研中，前文已给足信息时可直接删。例如接在上述版本说明后的“项目交付应以目标版本中已验证的模式为准”。读者需要作决策时，写出该对象特有的制约及后果。 |
| 为写作安排、图表用途或上一句作解释 | 先试删。给出器件与机架位置之后，“该配置说明了设备的组织方式”可省。图中省略关键连线、来源只覆盖某一代产品等会改变读法的信息，保留在相关图或事实旁。 |

删后通读剩余文字，允许一节结束在最后一个有用事实。若各处反复列同一组披露缺口，可在读者实际比较方案处集中说明。个别结论依赖的范围与该结论一起保留。

再单读仍含多条部署或验收动作的整段。有的段落换了位置、改了句式，读者读到的仍是一套适用于任何设备的操作清单。报告若只在解释某项测量，通常说到“计算满载能效还缺同工况的总吞吐和实际功耗”就已答完。起草时，若任务要求验收或产品机制会改变测试办法，再展开测量及运维步骤。润色已有稿件时，保留原有的独立操作要求。与本段主题关系较远时可建议移到操作章节，已有相应授权再移。

## 修复句内关系和技术称谓

- 检查泛化动词、因果连接和对偶。读“多个环节共同决定性能”时，找出材料给出的动作和中间环节，如“接收端可用缓冲空间限制上游本跳可发送的数据量”。上句已讲清机制时可删概括句。补写机制时保留原判断的强度，例如“减少重复发送”只支持说明减少了什么，若材料未给次数，就不能改成“源端只发送一次”。两个机制确有并列关系时写明各自主体。仅为凑成对偶的“前者、后者”宜还原为名称，条件分支的触发条件和结果须一一对应。
- 遇到多层“……的……的”、抽象搭配和过密的短句，把施事、动作、对象分别找出来，将条件移到它限定的动作旁。原文若只证明“资料描述了同一设备内的数据并行副本可复用权重”，应写“该资料说明，同一设备内的数据并行副本可复用权重”。写成“仅同设备可复用”增添了排他性结论。
- 同一机构、产品、版本和资料各用稳定称谓。首次承担技术主张时交代所属产品、资料身份及必要版本。同节指向唯一时可用简称，隔节或对照多个版本时恢复可辨名称。统一术语须保留精度、型号原文与测量口径。“词元/秒/用户”“词元/秒”“词元/焦耳”分别涉及每用户速率、未写明每用户分母的速率和能效。总吞吐还须由测试条件确认。引语、模型标识、命令参数及原始图中文字按原貌处理。

若作者只允许使用给定材料，首次释义可用材料已说明的功能。如材料只说某单元计算写入地址，可写“负责计算写地址的单元”，保留其标识。正式全称、厂商定义或没有明说的产品能力需另有依据。

## 查表格，再看实际页面

连读同节各幅图表的题注和正文引导句。正文若只说“图中展示……”，且宾语照抄图名，可直接从读者要看懂的对象落笔。图前可点明判断，图后指到支持它的曲线区段或部件位置。也可在一句中点出观察、位置与图号。表格需逐项检索时，点明查哪一行或按哪个条件查。涉及局部放大、示意图省略连线、单机与系统聚合值之分时，保留必要定位或口径。沿用指定的图号引用方式，改后核对正文指向。

逐行核对列名与内容。若“解释”列在每一行都重述项目名，可在有权限时删列。若其中一行交代“单节点峰值”或“厂商转述的第三方测试”，先为这条独有信息找到明确位置。表内证据范围正是比较目的时应保留。正文连续罗列模型、版本和功能时，确认哪些组合需要查找，再决定是否改为条件或兼容性表。每组数值仍要能找回对应型号、版本、单位和状态。正文保留能解释这些差异的判断。

把表中参数和正文的测量结果合写时，分别核对参数出处和实际测试工况。例如，同一篇文章列出设备支持的量化精度和一次测速结果，仍须由测试记录确认该次采用的精度，才能将两者连写。若工况出自另一份记录，应分别注明速度和工况的出处。现有证据不足时保留两项各自的归属，有权查证时可据原始记录补全。

Word 中看似空白的段落可能承载分页符、节属性、书签或图形。用文档结构和实际页面核对表题与表首行的位置，确认只是补白且排版授权允许时才调整。改动后重新渲染相关分页，核对图表题、跨页表头和交叉引用。

交付前，回到最先发现问题的具体位置，连读修改后的前后段，再横读同级标题、各章总结与相似主题。检查曾经重复的提醒是否换一种说法又出现，保留的相似句式是否承担必要比较，删并后能否就地找回条件和证据。只审阅时，对跨章问题给出代表位置与另一处对照，说明读者在哪一步遇到困难，以及建议从哪一句拆开、移到哪一节或保留哪个条件。整稿终检仍须覆盖全文。需要留审校记录时，记位置、实际改动及有意保留的理由即可。
