# 在下次会话继续写作或审阅

把断点保存在**用户文稿的持久工作目录**。同一目录可由不同会话或客户端重新打开。各命令中的 `--workspace` 始终指这个目录。从项目子目录重新进入时，可在当前目录到已知项目根目录之间查找已有的 `.unbot/`，再用原稿和范围核对候选。首次处理单份文稿且尚无约定时，使用原稿所在的可写持久目录。技能安装目录和临时下载目录仅用于读取工具或导入材料。可将编辑器的中间文件放入 `.unbot/work/` 下各任务独立的子目录。

## 进入任务

1. **先查询。** 调用[断点工具](../scripts/checkpoint.py)的 `resume`。用户只说“继续”时，在已确定的工作目录查询未完成任务。点名原稿、工作方式或范围时，用相应条件查找。写新稿、润色、只审阅、同时审阅和润色分别使用 `draft`、`polish`、`review`、`review-and-polish`。不要仅凭文件名相似或更新时间决定接哪份工作。
2. **按结果行动。** `ready` 表示找到一项候选且登记的输入通过核对。读取目标、范围、阶段、已存成果和下一步，与当前请求相符便直接恢复。如果用户交来不同的稿件或指定独立的新目标，按具体目的另取任务名建档。`ambiguous` 时先用用户已说明的原稿、范围或任务名缩小候选，仍有多项才列出可辨认的名称和范围。`blocked` 时按下文处置原稿变动。`none` 且本次是新任务时创建记录。若用户在找上次的结果，先用 `list --all` 和 `show` 检查是否已经完成，再处理缺失的工作目录或材料。
3. **首次保存。** 在开始写作或看第一页之前，记录作者的任务、目标语言、范围、交付格式及指定位置。用 `--input` 登记决定内容的原稿、数据与模板。只有粘贴文字时，将原文存成 UTF-8，并在 `start` 的同一次保存中以 `--artifact source.txt=文件路径` 收入。新会话需要的作者约束也写入首份状态。若新会话提供另外一段粘贴文字，先与已存原文核对。明确只在对话中处理且不许落盘时，按作者要求执行，说明此次无法本地续作。

## 何时保存，保存什么

每次 `save` 把状态与本批实际内容一同保存。得到新的版本号后，才将本批视为已完成。遇到保存失败，保留当前工作文件，只以最后成功返回的版本为准。恢复时如日志显示前一操作已经提交，以实际读回的版本为准。

| 工作 | 建议的保存时机 | 下次会话需要取回的内容 |
| --- | --- | --- |
| 依据材料起草 Word、PPT 或纯文本 | 确认范围后、每完成一节或数页、导出前 | 已写正文或可编辑稿、术语与证据对应、未解决的问题、下一节或页码 |
| 润色原稿 | 每完成一节或一段独立的技术说明 | 已改副本或完整改动清单、需保留的数值和格式、已核段落及未核段落 |
| 审阅 Word、PPT、TXT、Markdown | 每审完一组页或段落，包括已审且没有问题的位置 | 原稿提取清单、累积意见、关联位置、已读和未读范围、尚待回查的图表 |
| 导出、渲染、终检与交付 | 耗时操作前、成品重开验收后 | 实际文件、预期交付路径、已通过和仍欠缺的检查。双交付分别记录两份成果 |

进度应分配到能辨认的章节、段号或原稿页码。长章节可拆成更短的连续段落。若网络不可用，已经打开的本地资料和断点仍可使用；需要联网取得的来源记为待核，恢复连接后再核查。生成检查点之前只存在于聊天上下文或内存中的内容，需要从上个已存边界重做。

旧断点里若有未分类的意见，可照常取回。继续审阅时，在清单副本中对照原句、证据及原意见逐条补全 `category`、`issue` 和 `comment`，再把顶层的 `finding_schema` 设为 `2`，将这份清单随下一批成果保存。同一旧标签下可能包括不同问题，须按[当前批注判据](review-protocol.md#批注分类)分别判断。保留原稿中已有的他人批注和已验收的旧稿。

## 工具示例

以下为执行者使用的命令，作者无须记住任务编号。示例假定当前目录为技能目录，`项目目录` 是文稿工作目录的路径，其他相对文件路径按该工作目录解释。使用带空格的路径时加引号。

```text
python scripts/checkpoint.py --workspace "项目目录" resume --input "试验报告.docx" --mode review
python scripts/checkpoint.py --workspace "项目目录" start --task "试验报告全文审阅" --mode review --scope "全文含附录" --input "试验报告.docx" --state "首份状态.json"
```

状态是 UTF-8 JSON 对象。每次保存提供**完整的当前状态**，保留仍然有效的任务要求。以下示例为第 1 章已审完时的状态。正文、页清单和审阅意见另存为文件随状态一起提交。

```json
{
  "done": ["第 1 章及表 1 已读，核对了两条意见"],
  "next": "从第 2 章“测量条件”开始，对照表 2 核查结论的适用范围",
  "request": "只批注中文原文，保留已有意见，交付一份可编辑的 Word 审阅副本",
  "pending": ["附录 A 的时间窗尚待与表 2 对读"],
  "deliverables": ["试验报告-审阅.docx"]
}
```

将下例的 `ID` 换成任务编号。`save` 使用保存前的版本号 `N`，恢复时使用 `resume` 读回的当前版本号 `M`。每次保存只需附上新增或改变的文件。相同的附件名更新该文件，其余附件沿用上次保存的内容。审阅用一份累积意见清单。保存前先让编辑器写入正在修改的文件，确保快照包含本批改动。

```text
python scripts/checkpoint.py --workspace "项目目录" save ID --revision N --state "本批状态.json" --artifact "inventory.json=段落清单.json" --artifact "findings.json=累计意见.json"
python scripts/checkpoint.py --workspace "项目目录" resume
python scripts/checkpoint.py --workspace "项目目录" restore ID --revision M --to "本次恢复"
```

恢复目标应为尚未被文件、目录或链接占用的新路径，其父目录须已存在。`restore` 校验导出内容并再次核对原稿后，在新目录写入 `.unbot-restored.json` 回执。取回过程若中断，或原稿在恢复期间发生变化，普通恢复不会生成完成回执。先确认原稿版本，再选择新目录重试。重新打开取回的文件，对照已读范围和最后一处修改，再从 `next` 执行。需要重建审阅件时，从指纹一致的原稿加上累积意见一次生成，可避免在已有本轮批注的副本上重复加注。同一任务的另一会话已保存新版本时，先读回最新状态，核对并合并独立成果后再保存。断点库无法读写时保留现场，先修复访问问题或使用已有备份。

## 原稿变动与交付

- **原稿发生变化或缺失。** 登记为 `--input` 的原稿只记录路径与内容指纹，仍需保存原文件。先判断能否找回同一版本。若作者要处理新版，重新提取段号、页序和引文，重新检查受影响的上下文、引用及结论。可用 `restore ID --to "旧版对照" --for-reference` 单独取出旧断点的实际成果。只继承在新版逐项核实过的内容。先为新版成功建立新任务，再用 `retire ID --revision N` 封存被取代的旧任务。若当前权限不足，说明受影响的材料和可继续的部分。
- **只完成了部分导出。** 先检查预期目标位置。目标文件与已验收快照的内容指纹相同，直接复用。发现同名但内容不同的文件时，保留它，将成果另存到新位置。双交付逐份核对，补齐缺少的一份。
- **终检与结束。** 执行[全文终检](../SKILL.md#交付前的全文终检)。把已重开验收的文件保存为断点附件，记录目标路径和验收覆盖范围。随后用 `finish --verified-output` 把实际交付件逐份与对应附件核对。若文件在验收后又被改写，先保留改动并核查，重新验收选定的版本。只需聊天成稿且使用本地断点时，可将最终答复按同样方式保存为文本成果，再向作者返回文字。
- **取回已交付的版本。** 文件登记完成后再发交付消息。消息中断时，在匹配的完成记录中查看 `outputs` 的路径与状态。已删除或被改写的交付件可从完成记录恢复到新目录。此时若连原稿也已换版或缺失，使用 `--for-reference` 取回，并注明对应的原稿版本。

以下示例先保存验收附件，再登记交付。`N` 是保存前的版本号，`M` 使用这次 `save` 成功返回的新版本号。需要交付审阅件和润色件时，在同一条 `finish` 命令中分别列出两项 `--verified-output`，两份都核对成功才完成任务。

```text
python scripts/checkpoint.py --workspace "项目目录" save ID --revision N --state "终检状态.json" --artifact "reviewed.docx=验收副本/试验报告-审阅.docx"
python scripts/checkpoint.py --workspace "项目目录" finish ID --revision M --verified-output "reviewed.docx=试验报告-审阅.docx"
python scripts/checkpoint.py --workspace "项目目录" list --all
python scripts/checkpoint.py --workspace "项目目录" show ID
```

## 存放与迁移

使用本地可持久写入的工作目录。若客户端仅提供临时空间，且支持下载，可在所有保存操作结束后将完整工作目录连同 `.unbot/` 带到下次会话。工作目录内的源文件保持相对位置。存放在目录外的材料另行保存，迁移后须核对原路径和指纹。若无法保留目录，应及时说明实际可恢复的范围。移动或备份时应先结束写入，完整保留数据库及其日志文件。[SQLite 备份与恢复说明](https://sqlite.org/howtocorrupt.html#backup_or_restore_while_a_transaction_is_active)
