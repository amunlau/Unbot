# 从研究材料写成 Word 稿件

用户要求“写一份 Word 版报告”“把试验记录整理成论文初稿”时，交付可打开、可编辑的 `.docx`。由执行者在内部整理资料和制作文件，用户可以直接提供笔记、数据表或旧稿。若任务是给原稿批注，转到[Word 审阅流程](word-review.md)。

## 定稿前的三次核对

**先确定这份文件要回答什么。** 技术报告从试验目的、主要判断或待决问题选取主线；论文以研究问题组织证据；操作手册围绕任务、前提、动作和失败分支展开。将章节标题单独连读一次，核对读者在读到结论前是否已经知道研究对象、指标和比较基准。段落可以围绕一个判断安排若干句证据，无须给每段设置相同开场和小结。[Mensh 与 Kording 的论文结构指南](https://journals.plos.org/ploscompbiol/article?id=10.1371%2Fjournal.pcbi.1005619)

**再按主张核对材料。** 例如，笔记只写“试验组中位延迟 6.20 ms，对照组 7.10 ms；各测 12 次”。可以直接报告两组观测值和测量次数。材料没有说明离散程度、测试负载或差异检验时，不能写成“各工况下均显著改善”。核对数值所指的量、单位、精度和条件，保留原材料的有效数字。在工程要求中，将执行主体、触发条件、动作以及可验证的结果连起来写；阈值缺失时单列待补项。不要用“切实保障稳定运行”填补验收指标。[NIST 量值表达指南](https://www.nist.gov/pml/special-publication-811/nist-guide-si-chapter-7-rules-and-style-conventions-expressing-values) · [NASA 工程手册附录 C](https://www.nasa.gov/reference/system-engineering-handbook-appendix/)

**最后复核可追溯性。** 每个结果能追溯到哪张表、哪个试验记录或哪篇文献？题注、摘要和正文是否说的是同一组样本及同一种统计量？仅将核实过的文献编入参考文献。医学论文如有相应研究设计与期刊要求，再对照适用的报告清单；清单指出应交代的材料，无法替作者补齐未做的分析。[EQUATOR 对报告清单适用范围的说明](https://equator-network.org/about/reporting-guidelines.html)

## 已有文稿的润色

从原稿另存副本，按用户指定的章节和语言修改。定位到原段落或表格单元格，仅替换需要调整的文字。若句中含超链接、脚注、公式、文献域或上下标，沿原有对象编辑，保存后检查相应的链接、编号和格式。随附生成器用于新稿。

“干净成稿”默认指本轮编辑意见放在正文之外。原稿已有他人的批注或未决修订时，保留其状态。若用户明确要求清除批注，可在另存的交付副本中清除。遇到会改变事实的未决修订且取舍不明时，单列受影响的位置。用户指定“修订模式”时启用 Word 修订，在修订显示和最终显示两种视图中核对文字。只要求润色选段时，读取相邻内容用于理解，改动限于选段。

## 制作路径

**已有期刊或单位模板。** 从模板新建文档，用宿主的 Word 编辑工具或能够保留模板结构的制作者填写指定位置。沿用样式、章节编号、题注、参考文献域和页眉页脚。含原生公式、脚注、文献管理器字段、自动交叉引用、复杂图表或修订记录的文档也走这条路径。需要新增此类对象时使用支持相应对象的编辑器，交付前在 Word 中逐项检查，避免在格式往返中把它们拆成普通文字。[python-docx 关于模板、样式与另存文件的说明](https://python-docx.readthedocs.io/en/latest/user/documents.html)

**普通新稿，无指定模板。** 可将定稿整理为 UTF-8 JSON，使用随附的 [write_docx.py](../scripts/write_docx.py)生成新文档。脚本只负责排版，不调用模型，也不负责生成或核实主张。它支持标题、三级以内的章节标题、正文、警示、表题和普通矩形数据表。正式投稿所需的插图、公式、文献域、自动目录等请走上面的完整制作路径。

题名全文写入正文的标题段。题名在 255 个字符以内时，同时写入 Word 的“标题”属性。超过该长度时，生成器将此属性留空，文内题名仍完整保留。下例中的测量值用于展示格式。

```json
{
  "title": "采样延迟对比试验",
  "blocks": [
    {"type": "heading", "level": 1, "text": "1 测量结果"},
    {"type": "paragraph", "text": "两组各重复测量 12 次。表 1 列出各组的中位延迟。"},
    {"type": "caption", "text": "表 1　中位延迟"},
    {"type": "table", "headers": ["组别", "中位延迟（ms）"], "rows": [["试验组", "6.20"], ["对照组", "7.10"]]}
  ]
}
```

在 Skill 目录运行以下命令。使用有 `python-docx` 的 Python 环境；若该库不可用，可使用宿主提供的原生 Word 制作工具。中间 JSON 可放在临时目录，最终仅向用户交付所需文件。

```text
python scripts/write_docx.py draft.json report.docx
```

- 章节编号由作者根据文体写入标题文字。技术报告可沿用“1”“1.1”层次；期刊要求无编号标题时，直接使用“方法”“结果”等标题。脚本按给定文字排版，不会自动插入章号。
- 每个正文段落使用一个 `paragraph` 块。输入为纯文本；把 Markdown 星号、反引号或 LaTeX 命令直接放入文本会按原字符显示。普通数值和表格单元格使用字符串保存，以保留末位零和单位。表头须非空，数据行列数须与表头一致。
- 警示使用 `{"type":"warning","text":"校验超时时，不得覆盖原始数据。"}`。该块保留原句并加粗。警示应紧邻相应操作；区分“禁止”“要求”“建议”或“允许”。表题使用 `caption`，紧邻其后的表格，正文中的表号与表题一致。
- 仅创建新的 `.docx`；目标已存在时选新路径。未识别的字段或内容块会报错，避免遗漏输入材料而生成表面完整的文件。

## 成品核验

连读各节的主要判断，再逐项回到正文。核对概念在首次使用处是否清楚、结论所据的比较是否确实做过，以及移段后“上述条件”是否仍能找到对应位置。具体判据见[全文衔接与论证审阅](coherence-review.md)。

把以下核验与[全文终检](../SKILL.md#交付前的全文终检)落实在同一份将要交付的 Word 文件上。如有中英文摘要，分别通读，再将核心主张同正文和图表逐项对齐。修改后保存并重开，复查受影响的版面、文字和关联位置。

1. **内容。** 打开最终文件，将正文、表头、数据与定稿逐项对应，读回每个结果的对象、单位、边界、比较基准和引用。对警示，同时检查原句和所在位置。以下版式默认值适用于未指定模板的新稿，润色已有文件时按原稿或目标模板核验。
2. **结构。** 在 Word 导航窗格查看标题顺序和层级。总标题、章节标题、正文和表格各用相应样式，数据表设表头。普通生成器默认使用宋体和 Times New Roman，正文为黑色。东亚文字的校对语言设为简体中文，西文沿用默认英语。中文段落使用两字符首行缩进，标题、表格和警示独立设置。字体显示还取决于目标机器是否安装。[Microsoft 的标题和表格建议](https://support.microsoft.com/en-us/accessibility/word/make-your-word-documents-accessible-to-everyone-with-accessibility-assistant) · [Microsoft 字体分配说明](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.runfonts) · [字符单位首行缩进](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.indentation.firstlinechars)
3. **版面**：在 Word 打印布局或可信渲染结果中检查长标题、跨页表头、数字与单位换行、孤行、警示位置和页尾空白。普通生成器标记首行为可重复表头；需要按内容调整列宽、方向或分页时，在定稿后编辑并重新查看实际页面。只有结构检查而未查看版面时，交付时说明实际检查范围。[Microsoft 的跨页表头说明](https://support.microsoft.com/en-us/word/repeat-table-header-on-subsequent-pages)
