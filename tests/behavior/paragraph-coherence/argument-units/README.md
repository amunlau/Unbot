# 完整论证与段落边界验证

本组检查用户确认的“完整论证优先”：同一具体问题的模型、例证、解释与限定，在合并仍易读时优先成段；独立任务、较长论证阶段和真实阅读负担可支持分段。不以功能标签、连接词、固定字数或占页比例决定边界。运行规则见[完整论证优先](../../../../references/coherence-review.md#完整论证优先)。

## 方法与输入

共5项文字任务。三个任务复用用户提供的两组原例，分别只审阅、润色并整理段落、标准润色；另两个任务由未读取技能、旧用例或实现的独立作者编写，分别是合成计件验证材料起草、五个独立片段审阅。首轮规则冻结后维护者才读取新材料；复核判据与执行输入分开，未交给执行者。

两个执行会话各处理原例组或新材料组，只读对应的请求、材料及冻结技能，没有读取判据或其他结果，不进行网络核查。执行者沿用宿主默认模型；本组没有精确模型版本、采样参数或跨模型比较。每项只运行一次，同组内任务共用一个执行会话，不是每项独立清空上下文。

执行期间，独立规则审查发现现象表仍保留“同一问题需要几个论证步骤时可分别展开”的旧例外，缺少新规则要求的限制。修正该条后更新快照，两名执行者重新读取当前规则并复核全部任务，之后才交付最终结果；没有向执行者提供具体问题诊断、判据或预期答案。因此，本组是经过规则同步后的实际执行记录，不称为全程未接触其他规则版本的盲测。

[cases.json](cases.json)保存完整输入与判据；[runtime-snapshot.json](runtime-snapshot.json)记录18个运行文件（主说明与17份参考文件）的逐文件摘要、集合摘要，以及输入与输出摘要。集合摘要按 POSIX 相对路径排序，以 `路径 + NUL + 文件SHA-256` 组成每项，项间用 LF 分隔、末尾无 LF，再对 UTF-8 字节计算 SHA-256。README及测试文档不计入运行规则集合。

清单原有字段保留执行时的原始字节摘要，指向历史规则，不随当前技能更新。提交前补充的 `archive_lf_sha256` 覆盖本组输入及全部输出，用于 Git 归档或跨系统检出后的内容校验。其 `archive_hash_method` 为 `sha256-crlf-to-lf-v1`：只将 CRLF 转为 LF 后计算 SHA-256，不裁剪空白、不补末尾换行、不改正文。仓库 `.gitattributes` 会规范化文本换行，因此归档摘要可能与原始字节摘要不同；这不表示重新执行了行为任务。[归档完整性测试](../../../test_behavior_archives.py)校验覆盖范围、归档内容和历史规则集合摘要，不将旧快照与当前规则比较。
