# 章节入口规则的行为验证

本组针对用户确认的项目写作要求：标题与首段应就近交代对象、当前问题和必要联系；有说明任务转换时优先采用有内容的承接，紧邻简单关系直接点名，远引采用准确节号与名称。它不是对所有文体设定代词禁令。运行规则见[章节入口的重要规则](../../../../references/coherence-review.md#章节入口的重要规则)。

## 范围与方法

本次仅修改技能说明、参考规则和验证文档，没有修改文件处理脚本、批注数据格式或版本号。规则建立在上一轮篇章范围修订之上，未发布或同步到已安装副本。

4 项任务包括复用的映射原例审阅与普通润色，以及独立编写的字幕复核报告起草、5 个片段审阅。新材料的作者未读取技能、旧用例或实现。规则冻结后，维护者才读取这两份新输入。独立作者的初始判据曾允许在片段4替换正文中保留节号占位符；维护者在读取这组新材料的执行结果前按已确认的成稿要求纠正为“使用准确标题，待核说明放正文外”。输入材料未改变。

两个执行会话各处理两项任务，只读取冻结技能、相关参考文件以及各自的请求和材料，没有读取判据、他人输出或原例诊断。全部任务均为文字输出，没有改写实际 Word 或 PPT 文件。执行者沿用宿主默认模型，未提供可记录的精确模型版本或采样参数；每项仅运行一次，不作跨模型或稳定检出率结论。

[cases.json](cases.json)保存原始请求、材料和复核要点。[runtime-snapshot.json](runtime-snapshot.json)记录冻结的 `SKILL.md` 与 17 份参考文件的 SHA-256，以及原始输出摘要。集合摘要按 POSIX 相对路径排序，连接每项的 `路径 + NUL + 文件摘要`，各项以 LF 分隔、末尾无 LF，再对 UTF-8 字节计算 SHA-256。README 和测试文档不属于运行规则集合。

清单原有字段保留执行时的原始字节摘要，指向历史规则，不随当前技能更新。提交前补充的 `archive_lf_sha256` 覆盖本组输入及全部输出，用于 Git 归档或跨系统检出后的内容校验。其 `archive_hash_method` 为 `sha256-crlf-to-lf-v1`：只将 CRLF 转为 LF 后计算 SHA-256，不裁剪空白、不补末尾换行、不改正文。仓库 `.gitattributes` 会规范化文本换行，因此归档摘要可能与原始字节摘要不同；这不表示重新执行了行为任务。[归档完整性测试](../../../test_behavior_archives.py)校验覆盖范围、归档内容和历史规则集合摘要，不将旧快照与当前规则比较。
