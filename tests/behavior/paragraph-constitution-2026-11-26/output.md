# 任务A

## 前缀复用

晨星计算提供的推理服务软件 OrionServe 在各服务实例的本地内存中保存重复前缀的 KV 状态，供后续请求复用。OrionServe 在线技术文档集 v7.4 的 Prefix reuse（前缀复用）页面说明，不同实例不会自动交换缓存，请求去向因而影响复用机会。

## 服务配置

OrionServe 的批处理配置侧重累计完成量，交互配置侧重单请求等待。OrionServe 在线技术文档集 v7.4 的 Batch and interactive profiles（批处理与交互配置）页面说明了这一区别，并指出两种配置使用同一个客户端接口。

# 任务B

批量执行可减少数据库逐条处理记录时的函数调用。批量合适时，多条记录由一次操作共同处理；批量过大则可能增加等待时间和缓冲占用。执行器需根据请求分布选择批量。

批量执行通过合并记录处理减少函数调用，计划缓存则通过复用查询计划降低重复查询的准备成本。系统会复用结构相同且参数类型兼容的查询计划，减少重复解析和优化。查询仍需读取目标数据并完成运算；表结构变化后，可能需要使原计划失效并重新生成计划。

# 任务F

软件版本 R2 对模型 Q 开放文本前缀复用，但模型 Q 接受的图像请求不使用这项缓存。部署时应分别验证输入类型和缓存功能。

文本前缀缓存按完整页匹配；前缀至少形成一个匹配页后，才可复用该页，剩余输入继续计算。缓存按近期使用顺序淘汰，页被淘汰后便不能继续复用。

相同前缀的请求进入不同副本时，已有缓存状态无法自动共享，因此请求路由会影响缓存利用。增加副本后，各副本需要独立积累缓存状态；把请求分散到更多副本可以改变排队情况，但也会分散缓存复用机会。

节点接管功能尚未实现。

整理说明：将副本独立积累缓存状态的说明移至路由段；末段删去未说明具体评估内容的泛化收束，保留节点接管尚未实现的状态。
